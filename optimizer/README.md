# Этап 2. Стартовый набор

Условия и оценивание — в [задании](../stage-2.pdf). В набор входят:

| Файл | Назначение |
|---|---|
| `stella` | Готовый скрипт запуска предоставленного компилятора через Docker |
| [ir/README.md](ir/README.md) | Справочник записей IR, арифметики и правил сохранения |
| [ir/unit.schema.json](ir/unit.schema.json) | Структура JSON; для SIR доступны [грамматики](grammar/README.md) BNFC, Bison и ANTLR |
| `examples/` | Три примера входов, запросы и ожидаемые результаты |
| [REPORT.md](REPORT.md) | Шаблон вашего отчёта |

**`./stage2` — ваша будущая программа, её в наборе нет.** Создайте исполняемый файл или скрипт с таким именем, который запускает ваш оптимизатор. Он принимает режим первым аргументом, читает IR из stdin и пишет IR в stdout. Команды с `./stage2` ниже выполняются после реализации соответствующего режима. Команды с `./stella` доступны сразу.

## Предоставленный компилятор

Нужен Docker; в Windows используйте WSL. Исходный код компилятора и локальная установка Haskell не нужны.

```sh
docker pull fizruk/stella@sha256:f112c0c2e9d48d5860ecf6ccd1873ce86ff9deb3b714a858a2fbc90753b9de1b
./stella version
```

Образ закреплён по дайджесту, чтобы у всех был один и тот же компилятор; он собран для `linux/amd64` и `linux/arm64` и работает в Docker Desktop на macOS и Windows.

Запускайте команды из каталога `stage-2/`: он доступен контейнеру как `/work`. `STELLA_IMAGE` позволяет выбрать другой предоставленный образ. В отчёте укажите вывод `./stella version` и идентификатор образа из `docker image inspect fizruk/stella@sha256:f112c0c2e9d48d5860ecf6ccd1873ce86ff9deb3b714a858a2fbc90753b9de1b --format '{{.Id}}'`. Для проверок не требуется сборщик мусора из этапа 1.

Команды для этого этапа:

| Команда | Назначение |
|---|---|
| `compile-ir` | Перевести исходную Stella в CFG |
| `ir-check` | Проверить корректность IR |
| `ir-convert` | Перекодировать JSON/SIR без преобразования программы |
| `ir-run-source`, `ir-run` | Исполнить IR через интерпретатор |
| `ir-compile`, `ir-run-c` | Получить C или исполнить IR через C внутри Docker |

## Первый запуск без вашего оптимизатора

Пример `optimise.stella` дважды вычисляет `x + 1`, вычисляет неиспользуемое `x * 9` и выбирает ветвь по постоянному условию. Сначала получите IR и проверьте его исполнение:

```sh
./stella compile-ir examples/optimise.stella --to sir \
  -o input.sir --interface input.interface.json
./stella ir-check input.sir
./stella ir-run-source input.sir --interface input.interface.json \
  --request examples/optimise.request.json
```

Ожидается `{"result":{"i64":"10"},"events":[]}`; порядок ключей не важен. Файл `input.interface.json` описывает исходные типы. Сохраните его для запуска результата; вашей программе передаётся только IR.

Выберите JSON или SIR; второй формат реализовывать не требуется. Для JSON замените `--to sir` на `--to json` и используйте расширение `.json`. Целые числа в JSON записываются десятичными строками.

## Запуск вашего оптимизатора

Режим задаётся первым аргументом команды. Все режимы читают IR из stdin и печатают результат в stdout в выбранном формате (JSON или SIR).

| Команда | Вход | Выход | Назначение |
|---|---|---|---|
| `./stage2 ssa` | CFG | SSA | Построить SSA |
| `./stage2 sccp` | SSA | SSA | Выполнить условное продвижение констант |
| `./stage2 dce` | SSA | SSA | Удалить мёртвый код |
| `./stage2 cse` | SSA | SSA | Устранить общие подвыражения |
| `./stage2 lower-cfg` | SSA | CFG | Выйти из SSA в CFG |
| `./stage2 lower-functional` | SSA | Functional | Выйти из SSA в функциональную форму |
| `./stage2 pipeline-cfg` | CFG | CFG | Построить SSA, выполнить оптимизации и выйти в CFG |
| `./stage2 pipeline-functional` | CFG | Functional | Построить SSA, выполнить оптимизации и выйти в функциональную форму |

Обязательны `ssa`, `sccp`, `dce` и `cse`. Для выбранного выхода добавьте `lower-cfg` и `pipeline-cfg` либо `lower-functional` и `pipeline-functional`: всего шесть режимов.

После реализации режимов `ssa` и `cse` проверьте их по отдельности. Подготовьте SSA своим проходом:

```sh
./stage2 ssa < input.sir > input.ssa.sir
./stage2 cse < input.ssa.sir > output.ssa.sir
./stella ir-check output.ssa.sir
./stella ir-run-source output.ssa.sir --interface input.interface.json \
  --request examples/optimise.request.json
```

После реализации общего конвейера с выходом в CFG:

```sh
./stage2 pipeline-cfg < input.sir > output.sir
./stella ir-check output.sir
./stella ir-run-source output.sir --interface input.interface.json \
  --request examples/optimise.request.json
```

Для функционального выхода режим вашей программы — `pipeline-functional`. При чтении IR из stdin формат задаётся явно: `./stella ir-check - --from sir < output.sir`.

Для независимой проверки оптимизации можно написать SSA-вход вручную. Предоставленный компилятор не строит SSA, не оптимизирует IR и не выполняет ваши выходы из SSA. Ожидаемые ответы тестов определяйте самостоятельно; сравнивайте исполнение входного и выходного IR и проверяйте нужные структурные изменения.

Необязательный бонус — инкрементальное взаимодействие оптимизаций в общем конвейере: локально обновлять затронутые анализы, сохраняя пригодные данные об остальном коде. После изменений CFG допускается полный пересчёт. Подробные требования приведены в разделе «Расширенная часть» [задания](../stage-2.pdf); способ включения бонуса и сравнения с полным пересчётом опишите в `REPORT.md`. Дополнительного обязательного режима нет.

## Исполнение через C

Для обычных функций можно проверить результат через C внутри Docker:

```sh
./stella ir-run-c output.sir --interface input.interface.json \
  --request examples/optimise.request.json
```

Команда использует предоставленную библиотеку среды времени выполнения и заглушку на `malloc`. Устанавливать компилятор C или получать исходники этой библиотеки не нужно. Запрос и JSON-ответ такие же, как у `ir-run-source`. Успех даёт код 0, `arithmetic-zero` — 2, исчерпание ресурса — 3.

Заглушка хранит все выделения до завершения; по умолчанию лимит 64 МиБ. Его можно изменить через `--heap-bytes N`; лимиты шагов и обхода входа/результата — через `--steps N` и `--host-limit N`. Число шагов и расход памяти до и после оптимизации могут различаться. Процедуры и кадры пока исполняются только интерпретатором. Получить сам код C можно командой `./stella ir-compile output.sir --interface input.interface.json -o output.c`.

## Примеры и ваши тесты

`optimise` составлен для задания. Пример `swap.sir` из Stella показывает одновременные φ-присваивания в цикле: при `a = 8`, `b = 3`, `count = 1` он возвращает `-5`.

```sh
./stella ir-run examples/swap.sir --request examples/swap.request.json
./stella ir-convert examples/swap.sir --to json -o swap.json
```

Пример `runtime.sir` из Stella показывает процедуры (`routine`), описания объектов (`layout`) и кадров (`frame`), операции `runtime` с кучей и кадрами и завершения `tail`, `tail-entry` и `resume`. Исходная Stella такие модули не порождает, а закрытые тесты их содержат, в том числе с профилем `stella-ir-stack-v1`; ваш оптимизатор должен сохранять эти записи и обрабатывать тела процедур теми же анализами. Процедуры исполняются только интерпретатором: при `flag = true`, `n = 10` пример возвращает `16` и добавляет одно событие трассы.

```sh
./stella ir-check examples/runtime.sir
./stella ir-run examples/runtime.sir --request examples/runtime.request.json
```

`*.expected.json` задают ожидаемые наблюдения. Примеры показывают формат и способ запуска; собственные тесты, сборку и средства их запуска вы готовите сами.

Для своих тестов можно начинать со строгой Stella: `Int64`, `Bool`, `Nat`, `Unit`, кортежи, ссылки, `let`, ветвления, рекурсия именованных функций и `Nat::rec`. Функциональные значения, списки и суммы пока не поддерживаются. Перевода ленивой Stella через STG в этой поставке нет. Для нужной формы графа можно написать IR напрямую. Проверяйте, что интересующая вас операция осталась во входе вашего прохода.

Грамматики, JSON Schema, примеры чтения/печати, `swap.sir` и `runtime.sir` предоставлены проектом Stella; условия использования — в [LICENSE](LICENSE). Источники алгоритмов перечислены в задании. Автора заимствованного теста укажите в отчёте.
